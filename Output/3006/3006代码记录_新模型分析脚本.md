## 1. 脚本目的

该脚本用于检验 3006 新模型：

```text
Intention ~ Source_clean * Frame_clean * HealthC_c
```

也就是以行为意图为因变量，检验信息来源、信息框架、健康意识及其二阶/三阶交互项。

脚本特别强调两个原则：

1. `Source_clean` 和 `Frame_clean` 不直接使用 CSV 中已有的 `Source` / `Frame` 数值列，而是从 `随机元素` 中的 Stimuli A/B/C/D 标签重建。
2. 输出顺序沿用之前分析习惯：数据口径检查 → 信度 → 描述统计 → 相关 → GLM → simple effects → 假设检查 → 编码敏感性检查。

---

## 2. 输入文件

脚本读取：

```text
Data/R新模型/7100.csv
```

主要使用变量：

| Variable | Role |
|---|---|
| 随机元素 | 用于重建 Source_clean 和 Frame_clean |
| Intention | 因变量，行为意图复合分数 |
| HC | 调节变量，健康意识复合分数 |
| Source | 仅用于敏感性检查，不作为主模型解释依据 |
| Frame | 仅用于敏感性检查，不作为主模型解释依据 |
| 三个 Intention 题项 | 计算 Intention 信度 |
| 六个 HC 题项 | 计算 HealthC 信度 |

---

## 3. clean 编码规则

脚本根据 `随机元素` 重建实验条件：

| Stimuli | Source_clean | Frame_clean |
|---|---|---|
| Stimuli A. AI gain | AI coach | Gain frame |
| Stimuli B. AI loss | AI coach | Loss frame |
| Stimuli C. human gain | Human expert | Gain frame |
| Stimuli D. human loss | Human expert | Loss frame |

建模时使用 dummy coding：

| Variable | Coding |
|---|---|
| Source_AI | Human expert = 0, AI coach = 1 |
| Frame_Gain | Loss frame = 0, Gain frame = 1 |
| HC_c | HealthC - mean(HealthC) |

---

## 4. 模型结构

主模型为完整三重交互模型：

```text
Intention = b0
          + b1 Source_AI
          + b2 Frame_Gain
          + b3 HC_c
          + b4 Source_AI × Frame_Gain
          + b5 Source_AI × HC_c
          + b6 Frame_Gain × HC_c
          + b7 Source_AI × Frame_Gain × HC_c
          + error
```

脚本输出 Type-III 风格 partial F 检验：每次从 full model 中删除一个目标项，再比较 SSE 差异。

## 7. 与 SPSS 截图的对照诊断

组员截图报告：

```text
F(7, 179) = 20.374
R2 / eta-like value = .443
```

当前脚本基于 `Data/R新模型/7100.csv` 与 Stimuli clean 编码得到：

```text
F(7, 191) = 18.412
R2 = .403
```

因此当前 CSV 不能完全复现截图。最关键差异是残差自由度：

```text
SPSS 截图 df_error = 179
当前 clean 模型 df_error = 191
```

由于完整三重交互模型有 7 个预测项 + 1 个截距，SPSS 的 `df_error = 179` 暗示其有效样本约为：

```text
N = 179 + 8 = 187
```

而当前 CSV 主模型完整样本是：

```text
N = 199
```

这说明组员 SPSS 很可能使用了不同筛选规则、不同数据文件、额外缺失处理，或排除了某些个案。

## 8. 当前 clean 模型下的假设结论

基于 Stimuli clean 编码，当前结果为：

| Hypothesis | Result | Evidence |
|---|---|---|
| H1：HealthC 正向预测 Intention | supported | F = 41.122, p < .001, eta_p2 = .177 |
| H2：HealthC 调节 Source 效应 | not supported | F = 0.372, p = .543 |
| H3：HealthC 调节 Frame 效应 | supported | F = 14.970, p < .001, eta_p2 = .073 |
| H4：HealthC 调节 Source × Frame 联合效应 | not supported / marginal | F = 3.591, p = .060 |

注意：H4 接近显著，但未达到 .05 标准。

## 9. simple effects 结论

Source simple effects 对比为：

```text
AI coach - Human expert
```

| HealthC level | Estimate | p | Interpretation |
|---|---:|---:|---|
| Low HealthC | -0.298 | .0069 | 低 HealthC 下 Human > AI |
| Mean HealthC | -0.081 | .2946 | 不显著 |
| High HealthC | 0.136 | .2150 | 不显著 |

Frame simple effects 对比为：

```text
Gain frame - Loss frame
```

| HealthC level | Estimate | p | Interpretation |
|---|---:|---:|---|
| Low HealthC | 0.357 | .0013 | 低 HealthC 下 Gain > Loss |
| Mean HealthC | 0.093 | .2291 | 不显著 |
| High HealthC | -0.171 | .1210 | 方向反转但不显著 |

这与新模型理论方向部分吻合：低 HealthC 的确更受 human source 和 gain frame 影响；但高 HealthC 的 loss-frame 优势在当前 clean 数据中没有达到显著。

## 11. 是否符合新模型与假设

代码结构是符合新模型的：

```text
Intention ~ Source * Frame * HealthC_c
```

输出顺序也符合之前分析习惯：

```text
数据审计 -> 信度 -> 描述统计 -> 相关 -> GLM -> simple effects -> 假设检查 -> 敏感性检查
```

但是，当前 clean 数据结果并不完全符合组员截图中的假设结论：

- H1 成立。
- H3 成立。
- H2 在 clean 模型中不成立，但 simple effect 显示低 HealthC 下 Human > AI。
- H4 在 clean 模型中边界显著，但未达到 p < .05。
- 当前数据无法复现截图中的 `F(7,179)`。

因此，这份代码可以作为 3006 新模型的正式复现脚本，但在论文采用组员截图结果前，必须先确认 SPSS 使用的数据文件和筛选规则。

## 12. 后续建议

下一步最应该向组员确认：

1. SPSS 使用的是哪一个数据文件。
2. 为什么有效样本约为 187，而不是 199。
3. 是否删除了操纵检验失败、注意力检验失败、缺失值或其他样本。
4. Source/Frame 在 SPSS 中是按 Stimuli 标签编码，还是直接使用已有数值列。
5. HealthC_C 是均值中心化还是标准化。
6. simple effects 是 estimated marginal means 还是手动分组均值。

确认这些后，可以用本脚本调整筛选规则，再复现 SPSS 截图。
